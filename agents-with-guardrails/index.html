Four AI agents built in Claude Code, tested on purpose.

AgentsWithGuardRails

Each agent has one job and clear limits. I tested every one on made-up material with problems planted inside, to see what it caught, what it missed, and whether it stayed inside its limits.

RoleConcept, agent design, testing, review

Year2026

Built withClaude Code subagents, Claude Sonnet

Test dataAll fictional: no real people, emails or code

01 — The agents

One job each.

A subagent is a specialist Claude can hand a task to. Each one is a short file: a description of when to use it, the tools it may use, and instructions for how to work.

01

code-reviewer

Reviews code for security and performance problems and ranks each finding by severity, with a file, a line and a specific fix.

Guardrail: read-only, enforced twice. Its instructions forbid changing files, and a hook script checks every terminal command before it runs and blocks anything that would write.

02

data-entry

Pulls structured information out of emails and messy text and turns it into a clean document.

Guardrail: flags duplicates and missing details instead of guessing. Its tools aren't restricted yet (see next steps).

03

email-replier

Drafts friendly, professional first-draft replies to internal and customer emails.

Guardrail: drafts only. It never sends, and it marks every detail a person needs to confirm.

04

meeting-docs

Turns raw meeting notes into a structured document with decisions, action items, owners and deadlines.

Guardrail: surfaces unassigned tasks and labels its own assumptions instead of filling gaps silently.

02 — How I tested

Plant the problems first.

For each agent I used a made-up file with known problems built in. Knowing the answers in advance is the only way to judge an AI's work fairly.

AgentWhat was plantedResult
code-reviewerA Python file with 5 problems: a hardcoded key, SQL injection, a query inside a loop, network calls with no timeout, a password printed to logs5 of 5, plus extras
data-entryWorkshop sign-ups in mixed formats, one person listed twice, one missing email, one broken emailAll 3 caught
email-replierAn email with two requests: reschedule a meeting, and send a linkBoth handled
meeting-docsRough notes with 2 decisions, 3 owned tasks with deadlines, and 2 loose ends nobody claimedAll caught

04 — What I learned

Honest notes.

  • AI output varies between runs. I ran the code-reviewer twice. Both runs found all 5 planted problems with the same severity ranking, but one reported 7 issues and the other 8. Only the minor extras changed, which is why AI work still needs a person to review it.
  • Instructions are a guardrail; tools are a stronger one. The code-reviewer can only read, and a hook enforces it. The other three agents can currently use every tool, and two of them saved new files into the project. Restricting their tools is my next improvement.
  • Cautious isn't the same as complete. The data-entry agent never invented data, but it also left dates and phone numbers in mixed formats. Good agent design means deciding where the agent should fix things and where it should only flag them.
  • The best outputs showed their limits. [CONFIRM] tags, "unassigned" rows and labeled guesses made every agent's work easy to check.
