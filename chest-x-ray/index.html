ChestX-Ray

A desktop app that looks at a chest X-ray and predicts Normal or Pneumonia in about a second, with a confidence score and a spoken answer. It’s a learning project, not a medical diagnosis tool.

01 — Overview

The project

The goal

A fast, clear answer from an X-ray

I wanted to build an app where someone could upload or drag in a chest X-ray and get a clear result right away: Normal or Pneumonia, how confident the model is, and a spoken answer.

It was built as a student project for the i.c.stars Tech Expo, so it had to be quick, easy to use and reliable in front of an audience.

My role

Builder

I built it myself, using AI as a coding assistant. I trained the model, converted it into a faster format, built the desktop app and tested the results.

Tools: Python, TensorFlow and Keras, TensorFlow Lite, NumPy, Pillow and PyQt5.

02 — How it works

From image to answer

Training

Transfer learning with VGG16

Instead of training a model from scratch, I used transfer learning. I started with VGG16, an image model already trained on millions of everyday photos, kept its existing layers frozen and added a new final layer that chooses between two classes: Normal and Pneumonia.

I trained it on the public Chest X-Ray Images (Pneumonia) dataset. Each image was resized to 224 × 224 pixels, and I added small random changes (zoom, shear and flips) so the model would learn patterns instead of memorizing pictures. Training ran for 3 rounds (epochs).

Speed

Making the model fast enough for a demo

The trained model was saved as a large Keras file. I converted it to TensorFlow Lite, a lighter format made for running models quickly on everyday computers. That’s what brings the answer down to about a second.

The app

A simple window anyone can use

  • Upload an X-ray with a button, or drag and drop it onto the window.
  • The image appears as a preview while it’s analyzed.
  • The result shows in green for Normal or red for Pneumonia, with a confidence percentage.
  • The app says the result out loud.
  • A note on screen reminds people it’s a student demo, not a medical diagnosis.

03 — Challenges

What went wrong and how I fixed it

Bug 1

Almost every X-ray came back “Pneumonia”

At first, the app labeled nearly every image as Pneumonia. The cause was preprocessing: the app prepared images with a different method than the one used during training.

The fix was to prepare images in the app exactly the way they were prepared for training, by scaling the pixel values the same way. Lesson: a model only works when it sees data the same way it learned it.

Bug 2

The window froze on every click

An earlier version reloaded the whole model every time someone clicked the button, so the window froze.

I changed it to load the model once when the app opens, switched to the faster TensorFlow Lite model, and moved loading, predicting and the voice into background threads. Now the window stays responsive the whole time.

Bug 3

A Windows error on startup

On Windows, the app crashed with a “DLL load failed” error. I found that TensorFlow has to be loaded before the window library (PyQt5). Changing that order fixed it.

04 — Results

How well it worked, honestly

Results

19 out of 20

On 20 test X-rays (10 normal and 10 with pneumonia), the model got 19 right, or 95%.

That’s an encouraging start, but 20 images is a small check, not a full evaluation. A stronger test would use many more X-rays and look closely at missed pneumonia cases, because in health care a miss matters more than a false alarm.

Limits

What this app is not

This is a student learning project. It isn’t a medical device and shouldn’t be used to diagnose anyone. Reading X-rays is a doctor’s job; at most, a tool like this could help flag images for a person to review.

05 — Takeaways

What I learned

What I’m taking forward

  • Transfer learning lets you build on a model that already understands images, so a small project can still produce useful results.
  • The details matter: one mismatch in how images were prepared broke every prediction.
  • A good demo needs good UX too: loading once, staying responsive and giving a clear answer.
  • A high score on a small test isn’t the whole story. With AI in health, being honest about limits is part of building responsibly.
